# 📝 `im-not-ai` Technical Documentation & README Style Guide

This skill standardizes the high-impact, engineering-grade technical documentation style inspired by [`epoko77-ai/im-not-ai`](https://github.com/epoko77-ai/im-not-ai).

---

## 🏛️ Key Structure of an `im-not-ai` Style Document

Every technical README / architecture specification generated using this style MUST follow this structured sequence:

1. **Header & Status Badges**:
   - Clean, high-contrast Shields.io badges for: Architecture, GPU/CPU Engine, AI Model, Latency, Data Scale.
   - 1-sentence crystal clear Value Proposition with personalized context.

2. **⚡ 빠른 시작 (Quick Start)**:
   - Zero-friction copy-paste commands with prerequisites.

3. **💡 왜 이 플랫폼인가 (Why & Background)**:
   - Clear problem statement (e.g. Docker VM CPU limits, Hallucination) and how the 3 key solutions overcome them.

4. **🛡️ 4대 철칙 (Core Principles)**:
   - 4 non-negotiable architectural axioms (e.g. Zero Hallucination, Sub-second Latency, Context Preservation, Isolation).

5. **🏛️ 시스템 아키텍처 (System Architecture)**:
   - ASCII box diagram + Mermaid sequence/flowchart visualizing end-to-end dataflow.

6. **📊 실측 벤치마크 (Performance Matrix)**:
   - Direct quantitative comparison table (`🔴 Before` vs `🟢 After` vs `Improvement Rate`).

7. **🗺️ 실습 가이드 (Hands-on Labs / Stage Guide)**:
   - Tabular and modular roadmap with concrete command examples and concepts.

8. **🔧 실전 트러블슈팅 가이드 (Troubleshooting Playbook)**:
   - Common pitfall cases with Root Cause Analysis (원인) and Concrete Prescription (처방).

9. **📁 디렉터리 레이아웃 & 👥 크레딧 (Credits)**:
   - Accurate folder tree and authorship metadata.

---

## 🎨 Typography & Tone of Voice

- **Tone**: Authoritative, developer-friendly, clear, without generic AI fluff.
- **Formatting**: Rich GFM markdown, bold highlights, code formatting, clear emoji categorizers.
- **Visuals**: Structured ASCII art diagrams and Mermaid.js diagrams.
