4. Fluent API & Method Chaining

🍔 4장. 햄버거 주문서로 1초 만에 배우는 Fluent API 4단계 체이닝

Spring AI 코드를 보면 점(.)을 계속 이어 붙이는 모양(메서드 체이닝)이 나옵니다. 이것은 외계어가 아니라 "햄버거 주문서에 체크해서 점원에게 건네는 일상 대화"와 똑같습니다!

1 .prompt()

주문서를 펼친다

새로운 빈 프롬프트 편지지를 펼치는 시작 메서드입니다.

2 .user(질문)

질문을 적는다

"치즈 추가요, 양파 빼주세요"처럼 손님의 질문을 편지에 담습니다.

3 .call() 🌟

점원에게 제출한다

종료 호출: 이때 비로소 OpenAI/Ollama로 전파되어 실제 계산이 시작됩니다!

4 .content()

햄버거를 받는다

완성된 AI의 답변 문자열(String)을 포장에서 쏙 꺼냅니다.

초보자 가장 흔한 실수: .call()이나 .build() 종료 메서드를 안 부르면 주문서만 쓰고 점원에게 안 낸 꼴이라 아무 일도 일어나지 않습니다!

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

/**
 * 🍄 교재 35페이지 첫 실행 검증용 컨트롤러 (HelloAiController)
 * 
 * [비전공자 1초 해설]:
 * - 손님이 브라우저에서 'http://localhost:8085/hello?q=질문'을 입력하면,
 * - OpenAI(GPT-4o-mini) 모델이 실시간으로 답변을 작성하여 그대로 리턴합니다!
 */
@RestController // 🌟 자바 객체/문자열을 순수 데이터(HTTP 응답)로 즉시 반환하는 카운터 매니저
public class HelloAiController {

    // 🌟 AI 모델에게 요청을 보내는 표준 창구 (전화기)
    private final ChatClient chat;

    /**
     * 🌟 생성자 의존성 주입 (DI)
     * 스프링이 AiConfig에서 만들어둔 @Primary ChatClient(OpenAI)를 자동으로 주입해 줍니다.
     */
    public HelloAiController(ChatClient chat) {
        this.chat = chat;
    }

    /**
     * 🌟 교재 35쪽 핵심 메서드: /hello
     * 
     * @param q 손님이 전달한 질문 (미입력 시 기본값: "안녕하세요")
     * @return AI 모델이 생성한 답변 텍스트 문자열
     */
    @GetMapping("/hello")
    public String hello(@RequestParam(defaultValue = "안녕하세요") String q) {
        
        // 🌟 [교재 핵심] Fluent API 4단계 체이닝:
        // 1. prompt()  ➔ "인공지능에게 보낼 편지지를 펼친다!" (요청 구성 시작)
        // 2. user(q)   ➔ "손님이 입력한 질문(q)을 편지지에 적는다!" (사용자 프롬프트)
        // 3. call()    ➔ "우체통에 넣고 답변이 올 때까지 기다린다!" (동기 통신 호출)
        // 4. content() ➔ "답장 봉투를 뜯어서 알맹이 글자만 꺼낸다!" (텍스트 반환)
        return chat.prompt()
                .user(q)
                .call()
                .content();
    }
}

 */

@RequestMapping("/api/chat") // 🌟 공통 URL 접두사 매핑
public class ChatController {

    private final ChatClient chatClient;

    // 🌟 생성자 주입
    public ChatController(ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    // 🌟 GET http://localhost:8085/api/chat?message=질문내용
    @GetMapping
    public String chat(@RequestParam String message) {
        return chatClient.prompt()
                .user(message)
                .call()
                .content();
    }
}

package com.example.springai.config;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.ollama.OllamaChatModel;
import org.springframework.ai.openai.OpenAiChatModel;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Primary;

/**
 * ⚙️ Spring AI 멀티 프로바이더 설정 클래스 (AiConfig)
 */
@Configuration
public class AiConfig {

    /**
     * 🌟 1순위 기본 ChatClient (OpenAI GPT-4o-mini)
     * @Primary: 컨트롤러에서 ChatClient를 주입받을 때 1등으로 선택됩니다!
     */
    @Primary
    @Bean
    public ChatClient chatClient(OpenAiChatModel openAiChatModel) {
        return ChatClient.builder(openAiChatModel).build();
    }

    /**
     * 🌟 2순위 로컬 전용 ChatClient (Ollama qwen2.5:3b)

     */
    @Bean(name = "ollamaChatClient")
    public ChatClient ollamaChatClient(OllamaChatModel ollamaChatModel) {
        return ChatClient.builder(ollamaChatModel).build();
    }
}

1. Type System & Variable Naming

🏷️ 1. 왜 항상 단어를 2개씩 짝지어 적을까? ➔ `[종류/품명] [내 별명]`의 비밀

💡 마트 주문표 비유: 상품 분류(종류) + 내 물건 이름(별명)

Gradle Wrapper(gradlew)의 마법: 팀원마다 컴퓨터에 깔린 Gradle 버전이 다르면 빌드가 터집니다. ./gradlew는 프로젝트에 박혀 있는 정확한 버전(8.14.3)을 자동으로 실행해 주어, 어떤 컴퓨터에서 돌려도 100% 동일하게 실행되는 환경 격리 기술입니다.

BOM (Bill of Materials)이란?

부품 버전 맞춤 세트: OpenAI 라이브러리는 v1.0인데 Ollama 라이브러리가 v0.8이면 충돌이 납니다. spring-ai-bom은 모든 AI 부품들이 완벽하게 호환되는 황금 조합 버전을 한곳에서 통일 관리해 주는 안전벨트입니다.

JPA & Hibernate Persistence Context

🗄️ JPA 영속성 컨텍스트 4대 기적

자바 객체와 DB 테이블의 완벽한 1대1 통역
⚡

1. 1차 캐시 (First-Level Cache)

같은 트랜잭션 안에서 동일한 ID의 엔티티를 여러 번 조회하면, DB에 쿼리를 다시 날리지 않고 메모리 1차 캐시에서 0ms 만에 즉시 반환합니다.

📦

2. 쓰기 지연 (Write-Behind Buffering)

save()를 호출할 때마다 DB에 INSERT를 치지 않고 쓰기 지연 저장소에 모아두었다가, 트랜잭션이 끝나는 순간(commit) 한 번에 모아서 실행(FLUSH)합니다.

🔍

3. 변경 감지 (Dirty Checking) 🌟

update() 메서드를 부를 필요가 없습니다! 자바 객체의 필드값만 room.setRoomStatus(RoomStatus.ORDERED)로 변경하면, JPA가 스스로 알아채고 자동으로 UPDATE SQL을 전송합니다.

⏳

4. 지연 로딩 (Lazy Loading)

@ManyToOne(fetch = FetchType.LAZY)로 설정하여, 연관된 객체가 진짜 필요한 시점까지 불필요한 DB 조회를 미뤄 서버 성능을 극대화합니다.

@Service
@RequiredArgsConstructor // 🌟 final 변수를 스프링이 생성자로 자동 주입!
public class StockService {

    private final StockRepository stockRepository;

    /**
     * 🌟 [Dirty Checking (변경 감지)의 기적]
     * stockRepository.save()를 호출하지 않아도 @Transactional 안에서
     * stock.updateStock()으로 값만 바꾸면 트랜잭션 종료 시 JPA가 UPDATE SQL 자동 실행!
     */
    @Transactional
    public StockDto updateStockById(Long id, StockDto dto) {
        Stock stock = stockRepository.findById(id)
                .orElseThrow(() -> new IllegalArgumentException("해당 주식을 찾을 수 없습니다. id=" + id));

        stock.updateStock(dto.getName(), dto.getCurrentPrice());
        return StockDto.fromEntity(stock);
    }

    /**
     * 🌟 [Fast-Fail 선제 검증 패턴]
     * DB에서 없는 데이터를 삭제하려 할 때 500 서버 에러를 내지 않고
     * existsById로 0.001초 만에 확인 후 안전하게 삭제!
     */
    @Transactional
    public void deleteStockById(Long id) {
        if (!stockRepository.existsById(id)) {
            throw new IllegalArgumentException("삭제할 주식이 존재하지 않습니다. id=" + id);
        }
        stockRepository.deleteById(id);
    }
}

1. 1차 캐시 (First-Level Cache)

같은 트랜잭션 안에서 동일한 ID의 엔티티를 여러 번 조회하면, DB에 쿼리를 다시 날리지 않고 메모리 1차 캐시에서 0ms 만에 즉시 반환합니다.

📦

2. 쓰기 지연 (Write-Behind Buffering)

save()를 호출할 때마다 DB에 INSERT를 치지 않고 쓰기 지연 저장소에 모아두었다가, 트랜잭션이 끝나는 순간(commit) 한 번에 모아서 실행(FLUSH)합니다.

🔍

3. 변경 감지 (Dirty Checking) 🌟

update() 메서드를 부를 필요가 없습니다! 자바 객체의 필드값만 room.setRoomStatus(RoomStatus.ORDERED)로 변경하면, JPA가 스스로 알아채고 자동으로 UPDATE SQL을 전송합니다.

⏳

4. 지연 로딩 (Lazy Loading)

@ManyToOne(fetch = FetchType.LAZY)로 설정하여, 연관된 객체(예: 회원 정보)가 진짜 필요한 시점까지 불필요한 DB 조회를 미뤄 서버 성능을 극대화합니다.
